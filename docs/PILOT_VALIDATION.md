# Проверка пилота NARMA VISION

Этот документ разделяет три вида доказательств: техническая репетиция без
провайдеров, реальные эксплуатационные показатели и качество тренерских советов.
Зелёный CI и один готовый разбор не заменяют последние два вида проверки.

## Что уже можно измерять

В установленном API-контейнере доступен отчёт только для оператора:

```bash
cd /opt/narma/current/services/video
docker compose --project-name narma-video --env-file /opt/narma/secrets/video.env exec -T api \
  python -m narma_video.pilot_evidence --days 7
```

Команда выполняет агрегирующие SELECT в одной транзакции PostgreSQL
`REPEATABLE READ, READ ONLY`, с ограничением времени каждого запроса. Она не
запускает разборы, не делает запросов к моделям, не применяет миграции и не меняет
лимиты, резервы или расходы. Вывод не содержит email, никнеймы, идентификаторы
пользователей/матчей/заданий, названия файлов или ответы модели. Публичного API
для этих показателей нет. Не публикуйте полный env-файл или дамп базы.

| Поле | Что означает |
| --- | --- |
| `jobs_by_state` | Текущее состояние заданий, созданных за выбранный период; это не журнал всех переходов. |
| `ready_reports` | Отдельно готовые отчёты, сохранённый статус coaching и отчёты с успешным оплаченным вызовом OpenAI, связанным с тем же владельцем, заданием и хешем источника. |
| `ready_upload_to_last_update_proxy` | p50/p95 от создания загрузки до последнего изменения готовой строки. Включает загрузку, очередь и последующие изменения; **не время чистого парсинга и не SLA**. |
| `calls_created_in_window` | Число вызовов каждого провайдера и назначения, их статусы, известные списания и удержанные резервы. Для OpenAI отдельно p50/p95 между сохранёнными started/finished; это не полное время разбора. |
| `job_cohort_recorded_costs` | Все записанные расходы для заданий выбранного периода, включая расчёты, завершённые позже. Gemini-этапы и OpenAI сначала суммируются по заданию, поэтому соединение таблиц не умножает расходы. |
| `ready_fully_priced_jobs` | Готовые задания с хотя бы одним вызовом, у которого известна стоимость, и без вызовов с неизвестной стоимостью. Только они входят в среднее и p50/p95 расходов. |
| `current_cumulative_budgets` | Текущие накопительные потолки, расходы, резервы, сроки и разница с историей вызовов. Историческая корректировка может объяснять разницу; команда ничего не сверяет автоматически. |
| `ledger_link_integrity` | Вызовы без соответствующего задания того же владельца и несоответствия хеша OpenAI; такие данные нельзя выдавать за подтверждённый успешный разбор. |

`charged_microusd` — записанная приложением стоимость с его политикой округления
и консервативного учёта кеширования. Это **не сверенный счёт провайдера**. Один USD
равен 1 000 000 micro-USD. Неизвестная стоимость не превращается в ноль: резерв
сохраняется отдельно. Не добавляйте резерв к уже списанной сумме как фактическую
стоимость. Удалённые/обновлённые отчёты не образуют полной истории успешности.
Задания без вызовов исключены из среднего платного разбора. Расходы Hermes
показаны отдельно и не распределяются произвольно по матчам.

Текущий ранее разрешённый потолок OpenAI — **5 000 000 micro-USD до
2026-09-19T23:59:59Z**. Это не остаток баланса. Этот этап не увеличивает потолок,
не продлевает срок и не сбрасывает старые списания/резервы. Фактическое состояние
нужно читать из отчёта. Не следует выводить доступное число будущих разборов из
одной средней стоимости: перед вызовом требуется более высокий предельный резерв.

## Ограниченная техническая репетиция

```bash
# Только отдельный локальный PostgreSQL для тестов, никогда DSN приложения.
export TEST_DATABASE_URL='postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1/TEST_DATABASE'
PYTHONPATH=services/video python services/video/scripts/pilot_loadcheck.py --users 4 --concurrency 8
```

В GitHub Actions используется отдельный Compose-проект PostgreSQL. Контейнерный
хост `db` допускается только одновременно с `--ci-container` и
`NARMA_PILOT_CI_ISOLATED=1`. Произвольные серверы, `hostaddr`, `service` и входящие
настройки `search_path`/`options` отклоняются. Если `TEST_DATABASE_URL` отсутствует,
подстановка рабочего `DATABASE_URL` запрещена.
Унаследованные переменные libpq `PG*` также временно удаляются на весь запуск:
например, `PGHOSTADDR` или `PGSERVICE` не могут перенаправить локальный DSN на
другой сервер. После репетиции исходное окружение восстанавливается.

Каждый запуск создаёт случайную схему `pilot_rehearsal_<uuid>` и временный каталог
медиа. `search_path` содержит только эту схему, без `public`; миграции и тестовые
записи относятся только к ней. После запуска схема удаляется. Существующие
таблицы, аккаунты и бюджеты не очищаются. Скрипт не предназначен для запуска на
боевом сервере даже с локальным адресом базы.

Репетиция проходит через настоящие обработчики приложения:

1. До восьми синтетических аккаунтов входят с паролем через scrypt и получают
   защищённую cookie-сессию; проверяется `/api/session`.
2. Каждый отправляет две маленькие синтетические `.dem` через создание задания,
   загрузку части и `complete`. Проверяются идентификация и постановка в очередь.
3. Третье активное задание отклоняется штатной квотой. Анонимное чтение и чтение
   чужого задания отклоняются штатными проверками.
4. Два конкурирующих захвата каждого задания проверяют единственность lease.
   Затем задания завершаются специальной синтетической ошибкой, а не фальшивым
   готовым игровым отчётом.
5. Проверяется отсутствие любых новых записей вызовов OpenAI/Gemini и готовых
   игровых отчётов. Провайдерские ключи и фоновые обновления выключены.

Результат JSON содержит количество заданий/отказов и измеренные p50/p95 HTTP и
захвата очереди. Это ASGI внутри одного процесса с реальным PostgreSQL. Здесь
**не измеряются** интернет/nginx/TLS, обработка полного матча Java-парсером,
декодирование видео, ответы моделей и качество советов. Максимум — восемь
аккаунтов, шестнадцать потоков и шестнадцать очень маленьких заданий; это не
неограниченный стресс-тест. Нельзя объявлять такой результат пропускной
способностью Timeweb или числом клиентов для платного тарифа.

## Реальные матчи и ручная оценка

Для первого обзора качества собрать минимум десять разных матчей с двумя
примерами каждой позиции, включая победы и поражения и разные уровни подготовки.
Это минимальное покрытие сценариев для пилота, а не статистическое доказательство
роста рейтинга. Используются уже доступные владельцу разборы или добровольные
загрузки участников в пределах действующего бюджета. Автоматической платной
серии этот документ и репетиция не запускают.

Хранить исходники/отчёты в приватном контуре приложения. В обзорную таблицу
записывать псевдоним случая, версию релиза и результат проверки; не коммитить
никнеймы, email, полные ответы моделей и клиентские файлы. Проверяющий открывает
исходный эпизод и соответствующий отчёт. По возможности второй тренер оценивает
эпизод независимо до чтения AI-совета.

| Проверка | Критерий допуска к расширению пилота |
| --- | --- |
| Игрок и источник | Ноль разборов чужого игрока; источник и матч совпадают. Любой такой случай блокирует расширение. |
| Факты | Каждое проверенное утверждение о событии связано с существующим evidence/timecode; ноль придуманных чисел, покупок, смертей и таймингов. |
| Видимость и неопределённость | Совет не приписывает игроку сведения из тумана войны; видео не выдаётся за полный разбор матча. Отсутствующие данные названы явно. |
| Роль и контекст | Нет наказания поддержки за фарм керри; действия учитывают заявленную позицию и доступные факты, MMR не объявляется подтверждённым без источника. |
| Полезность | На каждый совет можно указать условие применения и проверяемое действие; следующая игра имеет одну понятную учебную задачу. |
| Устойчивость | Ошибка AI явно отделена от готовности парсинга; после повторного открытия нет второй оплаты того же уже обработанного источника. |
| Расходы | Известные списания и неизвестные резервы отражены раздельно; средняя стоимость публикуется только вместе с числом полностью оценённых заданий и исключениями. |

По полезности и ясности использовать шкалу 1–5: 1 — непригодно, 3 — полезно после
правки, 5 — конкретный совет, который можно выполнить и проверить. Предварительный
внутренний порог — не менее 4 в среднем и ни одного случая ниже 3. Числовой порог
сам по себе не отменяет блокирующую ошибку идентификации или фактов.

Шаблон записи (пустые значения означают **не проверено**):

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| P01 | — | — | — | — | — | — | — | — | Не проверено |
| P02 | — | — | — | — | — | — | — | — | Не проверено |

¹ Для реального времени пользовательского сценария отдельно зафиксировать начало
загрузки, приём в очередь и появление результата; не подменять их полем
`updated_at`. Сравнивать одиночный сценарий и небольшую заранее ограниченную
одновременную загрузку, наблюдая CPU, память, диск и длину очереди. Не назначать
число поддерживаемых пользователей до этих замеров.

Синтетические проверки контрактов локального Qwen, JSON-схем и защит от
подстановки инструкций остаются техническими тестами. Они не являются оценкой
качества OpenAI на реальных играх. В этом документе нет выдуманных результатов
реальных матчей или обещания роста рейтинга.
