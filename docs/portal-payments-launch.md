# Покупки в действующем кабинете NARMA

Это интеграция `services/video`, не старый D1-кабинет. Платежи по умолчанию выключены. Не активировать продажу до проверки точности отчётов, работоспособности обработки, документов и чеков.

## Что реализовано

Разовые продукты: один разбор 199 ₽, пять 799 ₽. Цены — проверяемая гипотеза пилота. Текущие отчёты доступны независимо от остатка. На оплаченный отчёт допускается до 40 успешных/выполняемых ответов тренера в общей истории по этому матчу; дополнительно действуют бюджет и доступность провайдера. Автопродления нет, платёжные реквизиты не сохраняются приложением.

В PostgreSQL сохраняется заказ с неизменным запросом, магазином, режимом и версией условий. Повторный запрос использует тот же ключ. Webhook только инициирует проверку: сумма, валюта, режим, магазин, paid и привязка заказа берутся из ответа API ЮKassa. Неизвестный исход не зачисляет баланс. После 23 часов неизвестный платёж без ID автоматически не создаётся повторно: у провайдера окно идемпотентности 24 часа.

Попытка резервируется после валидации полного реплея в транзакции постановки в очередь. PostgreSQL-триггер обрабатывает все завершения: готовый ИИ-комментарий расходует попытку, сбой/удаление незавершённой задачи/отсутствие комментария возвращает. Успешный купленный разбор при удалении не превращается в бесплатную новую попытку. Блокировка владельца исключает двойной расход последней попытки.

Запрос возврата замораживает весь неиспользованный остаток заказа. Если идут разборы, пользователь дожидается их завершения. Сумма пропорциональна остатку: 159,80 ₽ за единицу в пакете. Возврат требует подтверждения паролем владельца. Отсутствие ответа провайдера оставляет возврат в ожидании. Отмена провайдером освобождает остаток. Спор о качестве уже использованного разбора передаётся поддержке, без ограничения прав покупателя этой технической формой.

## Подключение продавца

В защищённом env API:

- `NARMA_BILLING_MODE=test`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` — отдельный тестовый магазин.
- `NARMA_SELLER_NAME`, `NARMA_SUPPORT_EMAIL`, `NARMA_TERMS_URL`, `NARMA_PRIVACY_URL`, `NARMA_TERMS_VERSION` — реальные сведения и опубликованные, согласованные с продавцом документы. Не подставлять реквизиты другого лица.
- `NARMA_RECEIPT_MODE=yookassa`, согласованный `NARMA_VAT_CODE`, `NARMA_RECEIPT_PAYMENT_MODE` (`full_payment`/`full_prepayment`) — схема определяется фактическим статусом продавца и договором, а не разработчиком. При предоплате отдельно обеспечить чек окончательного расчёта.
- Альтернатива: `NARMA_RECEIPT_MODE=external` только при уже работающей внешней фискализации. `NARMA_EXTERNAL_RECEIPTS_READY=1` — подтверждение оператора, а не реализация внешней кассы. Без неё режим не включается.
- `NARMA_FULFILLMENT_READY=1` ставится после реального сквозного теста. Для live дополнительно отдельные боевые ключи, `NARMA_BILLING_MODE=live`, `NARMA_BILLING_ENFORCE=1`, `NARMA_LIVE_PAYMENTS_APPROVED=1`.
- Callback: `https://<APP_ORIGIN>/api/billing/webhook` (APP_ORIGIN уже включает https, не дублировать). Подписки на payment.succeeded, payment.canceled, refund.succeeded. Проверить реальное уведомление из тестового магазина.

Ключи не писать в git, чат, issue или журнал. Существующий deploy сохраняет прежние env-переменные. Миграции аддитивные. Откат UI не требует удаления финансовых таблиц; их удаление недопустимо.

## Проверка до включения live

1. Проверить документы продавца: исполнитель/контакты, предмет услуги и лимиты, срок предоставления, пакет и срок использования, отсутствие продления, порядок поддержки/возврата, обработка email/Steam ID/реплеев и привлечение ИИ-провайдеров, сроки хранения. Это список исходных данных, не готовое юридическое заключение.
2. Пройти тестовую оплату/отмену/возврат в магазине; проверить чек покупки и возврата, а для аванса — окончательный чек. Автотесты используют синтетический провайдер и не подтверждают настройку магазина.
3. Сопоставить заказ, баланс, разбор, чат, возврат. Проверить сохранение после перезапуска и восстановления БД.
4. Проверить OpenAI-бюджет, обработчики, хранилище, актуальность модели. Покупка не увеличивает разрешённый бюджет ИИ. При выключенном/замороженном/пустом бюджете новые live-покупки блокируются.
5. Сверять журнал провайдера и PostgreSQL ежедневно и после сбоя. Неизвестные старые заказы, внешний возврат из кабинета ЮKassa, спор/чарджбэк и отменённый повторный возврат требуют оператора; автоматические повторные POST после окна запрещены. До организации этой сверки не открывать live.

## Полная себестоимость

Стоимость одного успешного пути = API-разбор + все ответы чата + платные повторные вызовы/ошибки + доля хостинга/хранения/бэкапов + комиссия эквайринга + фискализация + поддержка + возвраты/налоги. Предположение $0,30 не является измерением всего пути. Взять фактические charged/reserved/unknown из панели владельца, счёт хостинга и договор магазина; пересчитать валютные затраты по фактическому списанию. Нельзя обещать рентабельность по одной стоимости первого запроса.
