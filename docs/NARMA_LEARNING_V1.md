# Narma: первая версия учебного цикла

Версии: API `narma.learning.v1`, каталог `narma.curriculum.v1`, методика комментария `narma-coach.v3`. Этот документ описывает реализацию в коде. Факт публикации подтверждается отдельно успешным workflow и проверкой сервера.

## Что получает игрок

В разборе матча обновлён блок «В следующей игре». Игрок подтверждает позицию, выбирает один фокус и начинает серию из 3–5 игр. Это удобная длина тренировочного блока, а не обещание результата. Карточка объясняет вопрос, действие, причину, исключение и проверку простыми словами. Событие из реплея помогает выбрать момент для просмотра; оно не доказывает ошибку само по себе.

В пуле героев доступны шесть ступеней: линия, карта и ресурсы, риск, предметы, драки, самостоятельные решения. Каталог содержит 13 упражнений; общие доступны всем, задания линии и обзора фильтруются по вручную указанной позиции. Герой не определяет позицию автоматически.

Для каждого сочетания героя и позиции можно вести один активный фокус. Его можно поставить на паузу, завершить или возобновить. Ответ на вопрос и личная отметка сохраняются в аккаунте. Предусмотрены «выполнил», «частично», «не выполнил», «подходящей ситуации не было» и «нужно посмотреть». Исходный матч остаётся точкой отсчёта. В историю можно вернуться после перезагрузки страницы.

Карточки и личные проверки работают на уже сохранённых разборах; повторно загружать матч и ждать Gemini для этого не нужно. В верхнем блоке остаются герой, позиция и статистика; подробная справка и прежние советы свёрнуты. Существующая лента предметов с одной выбранной карточкой сохраняется.

## Реальные границы прогресса

Счётчик практики отражает личные проверки новых матчей того же героя и позиции. Он не является процентом правильных решений или доказанным уровнем навыка. Одна запись на матч не заменяет полный учёт всех ситуаций. Автоматического присвоения ступени, оценки «понимание игры выросло» и обещания MMR здесь нет.

Повторные загрузки одного матча канонизируются. Матчи из исходной истории, игры до начала задания и записи без подтверждённой даты не засчитываются как практика после постановки фокуса. Различающиеся известные сборки исключаются из серии; неизвестная сборка и неизвестный режим отмечаются как ограничение сравнения. Сборка не объявляется номером патча. Винрейт остаётся отдельной статистикой загруженной выборки.

План и ответы проверяются по текущему владельцу, закреплённому аккаунту, герою, ручной позиции, исходному файлу и хэшу отчёта. При смене роли, обновлении или удалении источника прежние отметки теряют актуальность; они не переносятся на другие события автоматически. Ответ игрока хранится отдельно от фактов и не отправляется модели как доказательство.

## API и хранение

Все маршруты требуют входа. Изменения требуют существующей защиты CSRF; тело ограничено 16 KiB. UUID чужой загрузки или плана не даёт доступ к нему.

| Маршрут | Назначение |
|---|---|
| `GET /api/learning?hero=…&position=…` | Каталог, собственная история и планы выбранной области |
| `GET /api/learning/reports/{job_id}` | Актуальный разбор матча, упражнения и допустимые ссылки на события |
| `POST /api/learning/plans` | Создать фокус по `job_id` и `exercise_id` |
| `PATCH /api/learning/plans/{id}` | Изменить состояние на `active`, `paused` или `completed` |
| `PUT /api/learning/plans/{id}/checks` | Сохранить ответ, самооценку и необязательную ссылку на событие |

Миграция `012_learning_curriculum.sql` добавляет `learning_plans` и `learning_checks`. Уникальный индекс и блокировка владельца защищают от параллельного создания двух активных фокусов в одной области. Повтор одинакового запроса не создаёт новую практику или вторую проверку. GET не записывает метаданные пула; чтение использует согласованный снимок.

Каталог находится в `services/video/narma_video/curriculum.py`, API и проверки области — в `learning.py`. Клиент использует эти данные в `static/portal.js`. Название `v1` в каталоге — идентификатор упражнения на обзор, а не версия API.

## Модель и публикация

Для последующих тренерских комментариев `replay_coach.py` передаёт существующему Gemini ручную позицию и актуальное упражнение. Перед чтением проверяются владелец, закреплённый игрок, исходный реплей и действующая аренда задания. Изменившийся контекст не переносит прежний комментарий как новый. Изменение prompt не инициирует повторных платных вызовов.

Gemini → OpenAI → Hermes остаётся отдельной будущей интеграцией. В этом релизе нет нового OpenAI-провайдера и не запускается выключенный Hermes. Обычная публикация сохраняет его состояние и бюджет; подробности в [операционном описании](../ops/timeweb/CURRICULUM_RELEASE.md).

Проверки включают каталог и происхождение событий, изоляцию владельцев, дубликаты, изменение роли/источника, даты, идемпотентность, CSRF, сохранение ответов, мобильный интерфейс и неизменность provider ledger при проверке существующих отчётов. Конкурентные сценарии проверяются на обычном PostgreSQL в CI; локальная совместимая БД не заменяет этот этап.
